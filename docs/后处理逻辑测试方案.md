# 后处理逻辑测试方案

## 一、概述

本方案旨在建立一套完善的后处理逻辑测试体系，确保每次调整后处理逻辑时不会导致性能退化。测试体系包含合成测试集和真实数据集两部分，从多个维度进行评估，并通过难度加权机制对复杂场景给予更高权重。

## 二、数据集设计

### 2.1 合成测试集

合成测试集包含20个精心设计的测试用例，覆盖各种边界条件和特殊场景。

#### 2.1.1 难度等级划分

| 难度 | 用例数 | 权重系数 | 场景描述 |
|------|--------|----------|----------|

| **medium** | 5 | ×1.5 | 完全共享边界、相邻共享边界、宽度1字符、密集边界噪声、连续共享边界 |

#### 2.2.2 难度分类规则

- **simple**：字符数 < 2，或所有字符间距均匀（最小间距 > 2像素）且无共享边界
- **medium**：存在1个共享边界，或最小间距 ≤ 2像素但平均间距 ≥ 字符宽度的20%
- **hard**：存在≥2个共享边界，或多个空白分隔区域，或平均间距 < 字符宽度的20%

#### 2.2.3 数据缓存机制

使用最佳模型对标注数据进行推理，缓存以下内容：

- `pred_class`：模型预测的类别数组（0/1/2）
- `pred_prob`：模型预测的概率数组（3通道）
- `gt_intervals`：人工标注的字符区间
- `pred_intervals`：后处理后的预测区间
- `difficulty`：自动分类的难度等级

## 三、评价指标体系

### 3.1 指标定义

| 指标 | 权重 | 描述 | 计算公式 |
|------|------|------|----------|
| **字符数量准确率** | 0.2 | 预测字符数与真实字符数的匹配程度 | `1 - abs(pred_count - gt_count) / max(gt_count, 1)` |
| **边界位置准确度** | 0.2 | 预测边界位置与真实边界的平均绝对误差（归一化） | `1 - MAE / max_boundary_position` |
| **过分割抵抗率** | 0.15 | 抵抗过度分割的能力 | `1 - max(0, pred_count - gt_count) / gt_count` |
| **欠分割抵抗率** | 0.15 | 抵抗欠分割的能力 | `1 - max(0, gt_count - pred_count) / gt_count` |
| **共享边界识别率** | 0.15 | 共享边界位置的F1分数 | `2 * precision * recall / (precision + recall)` |
| **区间IoU** | 0.15 | 预测区间与真实区间的像素级交并比 | `|pred ∩ gt| / |pred ∪ gt|` |

### 3.2 指标计算细节

#### 3.2.1 字符数量准确率

```
char_count_acc = 1.0, if pred_count == gt_count
char_count_acc = max(0, 1 - abs(pred_count - gt_count) / max(gt_count, 1)), otherwise
```

#### 3.2.2 边界位置准确度

1. 收集所有预测边界和真实边界位置
2. 按位置排序
3. 计算对应位置的绝对误差平均值（MAE）
4. 归一化到[0,1]区间

#### 3.2.3 共享边界识别率

使用F1分数评估共享边界识别的准确性：

```
TP = 预测正确的共享边界位置数量
FP = 预测错误的共享边界位置数量
FN = 未预测到的共享边界位置数量

precision = TP / (TP + FP)
recall = TP / (TP + FN)
F1 = 2 * precision * recall / (precision + recall)
```

#### 3.2.4 区间IoU

基于像素级集合运算计算：

```
pred_union = {所有预测区间覆盖的像素}
gt_union = {所有真实区间覆盖的像素}

IoU = |pred_union ∩ gt_union| / |pred_union ∪ gt_union|
```

## 四、加权机制

### 4.1 难度加权

| 难度等级 | 权重系数 | 含义 |
|----------|----------|------|
| simple | ×1.0 | 基础场景，必须全部通过 |
| medium | ×1.5 | 中等难度，共享边界等场景 |
| hard | ×2.0 | 高难度，粘连字符、噪声等场景 |

### 4.2 综合分数计算

```
样本加权分数 = Σ(指标分数 × 指标权重) × 难度系数
总体分数 = 所有样本加权分数的平均值

指标权重分配：
- 字符数量准确率：0.2
- 边界位置准确度：0.2
- 过分割抵抗率：0.15
- 欠分割抵抗率：0.15
- 共享边界识别率：0.15
- 区间IoU：0.15
```

### 4.3 合成测试与真实数据的组合

```
综合评估 = (合成测试分数 × 合成测试权重) + (真实数据分数 × 真实数据权重)
合成测试权重 = 0.3
真实数据权重 = 0.7
```

**实现说明**：该权重机制已在 `postprocess_evaluator.py` 的 `run_full_evaluation()` 函数中实现，确保文档与代码一致。

## 五、测试执行流程

### 5.1 首次使用

```bash
# 生成基准数据集（合成测试集 + 真实数据推理缓存）
python create_benchmark_dataset.py

# 运行回归测试，建立基线分数
python tests/postprocess_evaluator.py
```

### 5.2 日常回归测试

```bash
# 修改后处理逻辑后，运行回归测试
python tests/postprocess_evaluator.py
```

### 5.3 新增标注数据后

```bash
# 更新基准数据集
python create_benchmark_dataset.py

# 运行回归测试
python tests/postprocess_evaluator.py
```

### 5.4 判断标准

| 检查项 | 达标条件 | 说明 |
|--------|----------|------|
| 阻塞性测试 | 所有用例通过 | 基础功能不退化（无 known_issue 的测试用例） |
| 已知问题测试 | 不新增失败 | 已跟踪的问题不应恶化 |
| 综合分数 | ≥ 0.8 | 整体效果达标 |
| 真实数据分数 | 不低于基线 | 实际效果不下降 |

### 5.5 已知问题跟踪机制

测试用例分为两类：

1. **阻塞性测试（Blocker）**：无 `known_issue` 标记的测试用例，必须全部通过
2. **已知问题测试（Known Issue）**：有 `known_issue` 标记的测试用例，记录当前已知的 bug，用于跟踪修复进度

当修复某个已知问题后，移除对应的 `known_issue` 标记，该用例自动升级为阻塞性测试。

## 六、数据添加策略

### 6.1 新标注数据

每次新增标注后，重新运行 `create_benchmark_dataset.py` 更新基准数据集。

### 6.2 失败案例

当合成测试失败时：
1. 分析失败原因
2. 确认是否是后处理逻辑问题
3. 如果是合理的行为变更，更新测试用例期望值
4. 如果是Bug，修复后处理逻辑

### 6.3 边界场景

遇到新的边界场景（如特殊粘连模式、罕见噪声模式）时，添加到合成测试集。

### 6.4 模型更新

更换模型后，重新生成真实数据推理缓存：

```bash
python create_benchmark_dataset.py
```

### 8.5 问题分析

1. **共享边界识别率偏低（0.0847）**：主要原因是模型推理产生大量宽度为1-2的噪声区间，导致误识别了大量伪共享边界。

2. **过分割抵抗率偏低（0.5458）**：模型预测的边界点过于密集，后处理未能有效过滤噪声边界。

3. **简单场景分数偏低（0.5695）**：样本量太少（仅3个），代表性不足，需要补充更多简单场景的标注数据。

## 九、维护建议

1. **定期更新基准**：每两周或新增标注数据后，更新基准数据集。

2. **补充测试用例**：针对发现的新问题，及时添加对应的合成测试用例。

3. **优化后处理逻辑**：重点关注过分割问题和共享边界识别问题，提升这两项指标。

4. **增加简单场景标注**：补充更多简单场景的标注数据，提高基准数据集的代表性。
