## 一、设计背景

### 1.1 问题定义

字符分割模型的评测需要回答以下问题：
- 模型切对了多少字符？（准确率）
- 模型多切了多少？少切了多少？（过分割/欠分割）
- 多切的字符是什么类型？（脏点、半个字符、还是其他）
- 少切的字符是什么类型？（真漏检、还是被合并了）
- 边界位置偏了多少像素？（边界精度）

### 1.2 旧评测体系的问题

| 问题 | 说明 |
|------|------|
| greedy_match 重复调用 | 6个评测函数各调1次，共6次 |
| 欠分割只有一类 | 漏检和合并混在一起，无法区分错误性质 |
| 过分割粒度粗 | 只统计多余字符数量，不区分脏点/碎片/其他 |
| 无标准 P/R/F1 | 缺少分类/检测任务最通用的指标 |
| 无字符级档案 | 只有汇总数字，无法定位具体哪个字符有问题 |
| 匹配阈值不明确 | half_char 用0.3-0.7，但"correct"无明确定义 |

### 1.3 新体系核心改进

1. **build_char_archive()**：只调1次 greedy_match，建立每个GT/Pred字符的完整状态档案
2. **字符级状态分类**：GT 6种状态、Pred 5种状态
3. **标准 P/R/F1 指标**
4. **字符级跨模型对比**：找出具体哪个字符从模型A到模型B变好/变差了

## 二、核心算法

### 2.1 贪心匹配（greedy_match）

所有评测指标的基础。对预测字符和标注字符进行一对一匹配。

**算法流程**：
1. 构建 IoU 矩阵（pred_count × gt_count）
2. 循环选择矩阵中 IoU 最大的格子
3. 若最大 IoU < 阈值，停止
4. 将该 (pred, gt) 配对，清零对应行和列
5. 返回：匹配对、未匹配pred列表、未匹配gt列表

**排序剪枝优化**：对 pred 和 gt 按 col_start 排序，利用区间单调性跳过不可能重叠的区间对，将计算量从 O(n×m) 降至接近 O(n+m)。

### 2.2 字符档案构建（build_char_archive）

在 greedy_match 基础上，为每个字符计算完整的重叠关系和状态：

```
greedy_match (1次)
    │
    ├── pred_to_gt / gt_to_pred（匹配对）
    ├── unmatched_pred / unmatched_gt（未匹配）
    │
    ▼
计算 overlapping 关系
    │
    ├── gt_overlapping_preds: 每个GT被哪些pred覆盖
    └── pred_overlapping_gts: 每个pred覆盖了哪些GT
    │
    ▼
状态判定
    ├── GT: correct / half_char / over_segmented / merged / missed / borderline
    └── Pred: correct / half_char / dirty_spot / sliver / extra
```

## 三、阈值设计

### 3.1 匹配与状态阈值

| 阈值 | 值 | 含义 | 设计理由 |
|------|:--:|------|---------|
| greedy_match 门限 | 0.1 | IoU < 0.1 不匹配 | 宽松匹配，尽量配对，后面再细分类 |
| correct 分界线 | 0.7 | IoU ≥ 0.7 为正确 | 边界偏移约5像素以内（正常字宽35px） |
| half_char 下界 | 0.3 | 0.3 ≤ IoU < 0.7 为半个字符 | 至少重叠30%才认为"和这个字有关系" |
| dirty_spot 宽度 | 20% × 中位数 | 宽度 < 中位数×20% 为候选脏点 | 92.7%的脏点宽度 < 正常字宽的20% |
| dirty_spot 重叠 | 10% | 重叠率 < 10% 为脏点 | 脏点在空白处，与任何GT重叠极少 |
| sliver 重叠 | 30% | 重叠率 ≥ 30% 为碎片 | 从汉字身上拆下的半块仍有较多重叠 |

### 3.2 为什么选 IoU=0.7 作为 correct 分界线

- 正常汉字宽度约35像素
- IoU=0.7 意味着边界偏移约5像素（35×0.15×2≈5）
- 评测数据显示 97.65% 的边界偏移在3像素以内，对应IoU在0.8+
- IoU=0.5 意味着偏移约8-9像素，已经是明显错误
- 0.7 能区分"真正正确"和"勉强匹配"

## 四、GT字符状态分类（6种）

以标注字符为中心，根据匹配结果和重叠关系判定状态：

| 状态 | 判定条件 | 语义 | 错误性质 |
|------|---------|------|---------|
| **correct** | 贪心匹配成功 且 IoU ≥ 0.7 | 切得准，边界对齐 | 无错误 |
| **half_char** | 贪心匹配成功 且 0.3 ≤ IoU < 0.7 且 overlapping_preds < 2 | 只切到了字的一部分 | 边界检测能力不足 |
| **over_segmented** | 贪心匹配成功 且 0.3 ≤ IoU < 0.7 且 overlapping_preds ≥ 2 | 一个字被拆成了多块 | 过分割（拆分型） |
| **borderline** | 贪心匹配成功 且 IoU < 0.3 | 勉强匹配到，边界差很多 | 严重边界错误 |
| **merged** | 贪心匹配失败 但 有pred覆盖它 | 被旁边的pred吞并了 | 欠分割（合并型） |
| **missed** | 贪心匹配失败 且 无pred重叠 | 真漏检，模型完全没切 | 欠分割（漏检型） |

### merged vs missed 的区别

```
标注:  [字A] [字B] [字C]
情况1: [字A]        [字C]      ← 字B missed（模型没切这个位置）
情况2: [  字AB  ]   [字C]      ← 字B merged（切了但被字A的区间吞并了）
```

两种错误性质不同：
- **missed**：模型对该位置没激活 → 特征不够/阈值太高
- **merged**：模型激活了但边界不清晰 → 边界检测能力问题

## 五、Pred字符状态分类（5种）

以预测字符为中心，根据匹配结果和重叠关系判定状态：

| 状态 | 判定条件 | 语义 | 错误性质 |
|------|---------|------|---------|
| **correct** | 贪心匹配成功 且 IoU ≥ 0.7 | 对的 | 无错误 |
| **half_char** | 贪心匹配成功 且 IoU < 0.7 | 切了半个字 | 边界不准 |
| **dirty_spot** | 未匹配 + 宽度 < 中位数×20% + 重叠率 < 10% | 印刷脏点被误切 | 标签污染/特征不足 |
| **sliver** | 未匹配 + 与某GT重叠率 ≥ 30% | 从汉字身上拆下的碎片 | 过分割（拆分型） |
| **extra** | 未匹配 + 不属于上面两类 | 其他多余字符 | 其他 |

### dirty_spot vs sliver 的区别

```
标注:  [  字明  ]              [字C]
情况1: [日] [月] [脏]          [字C]  ← "脏"是dirty_spot（空白处的小黑点）
情况2: [日] [月]              [字C]  ← "日""月"是sliver（从"明"身上拆下的）
```

## 六、指标体系（15个指标）

### 6.1 核心标准指标（3个）

| # | 指标 | 公式 | 衡量什么 |
|:-:|------|------|---------|
| 1 | **Precision** | pred.correct / total_pred | 预测里多少是对的 |
| 2 | **Recall** | gt.correct / total_gt | 标注里多少被切对了 |
| 3 | **F1 Score** | 2×P×R/(P+R) | 综合性能 |

### 6.2 欠分割视角（3个）

| # | 指标 | 公式 | 含义 |
|:-:|------|------|------|
| 4 | **Missed Rate** | gt.missed / total_gt | 真漏检率 |
| 5 | **Merged Rate** | gt.merged / total_gt | 被合并率 |
| 6 | **Under-Seg Rate** | (missed + merged) / total_gt | 总欠分割率 |

### 6.3 过分割视角（4个）

| # | 指标 | 公式 | 含义 |
|:-:|------|------|------|
| 7 | **Over-Seg Rate** | gt.over_segmented / total_gt | 被拆分率 |
| 8 | **Dirty Spot Rate** | pred.dirty_spot / total_pred | 脏点率 |
| 9 | **Sliver Rate** | pred.sliver / total_pred | 碎片率 |
| 10 | **Extra Rate** | pred.extra / total_pred | 其他多余字符率 |

### 6.4 质量指标（5个）

| # | 指标 | 公式 | 含义 |
|:-:|------|------|------|
| 11 | **Matched IoU** | mean(匹配对的IoU) | 匹配字符的边界质量 |
| 12 | **Boundary MAE** | mean(\|start_err\| + \|end_err\|) / 2 | 像素级边界精度 |
| 13 | **Width Deviation** | mean(\|pred_w - gt_w\|) / median_gt_w | 相对宽度偏差 |
| 14 | **Matched Pair Count** | matched_pairs | 基本统计 |
| 15 | **Count Match Rate** | (pred_count == gt_count) 的比例 | 数量匹配率 |

## 七、综合评分（0-100分）

### 7.1 权重设计

| 指标 | 权重 | 设计理由 |
|------|:----:|---------|
| F1 Score | 30% | 核心综合指标，反映精确率和召回率 |
| 边界准确率 | 20% | 像素级边界精度 |
| 过分割抵抗率 | 15% | 当前最大问题，权重高 |
| 欠分割抵抗率 | 15% | 含merged，反映边界检测能力 |
| 脏点抵抗率 | 10% | 数据清洗效果的直接体现 |
| 宽度准确率 | 10% | 字符宽度偏差 |

### 7.2 计算公式

```
score = F1 × 30 + boundary_acc × 20
      + (1 - over_seg_ratio) × 15
      + (1 - under_seg_ratio) × 15
      + (1 - dirty_spot_ratio) × 10
      + (1 - width_error_ratio) × 10
```

## 八、字符级跨模型对比

### 8.1 功能说明

对比两个模型版本在同一批标注数据上的表现，找出**具体哪个字符**从版本A到版本B变好或变差了。

### 8.2 对比维度

| 类别 | 含义 |
|------|------|
| both_correct | 两个模型都切对了 |
| both_wrong_same | 两个模型都切错了，且错误类型相同 |
| improved | A错了B对了（改善） |
| degraded | A对了B错了（退化） |
| both_wrong_changed | 两个模型都切错了，但错误类型不同 |

### 8.3 输出示例

```
总GT字符数: 2051
  两个模型都正确: 1930 (94.10%)
  两个模型都错误(同类): 16 (0.78%)
  改善的字符(A错→B对): 23 (1.12%)
  退化的字符(A对→B错): 5 (0.24%)
  都错但类型不同: 77 (3.76%)
```

## 九、CLI使用方法

### 9.1 评测模式

```bash
# 使用推理版本目录评测
python evaluate_model.py --project-id proj_20260725_225531 --model-version v0724 --output eval_v0724.json

# 使用项目model_jsons目录评测
python evaluate_model.py --project-id proj_20260725_225531 --output eval_result.json
```

### 9.2 指标级对比

```bash
python evaluate_model.py --compare eval_v0724.json eval_v0808.json
```

输出每个指标的变化值和方向（改善/退化）。

### 9.3 字符级对比

```bash
python evaluate_model.py --compare-char eval_v0724.json eval_v0808.json
```

输出每个字符的状态变化，并保存详细对比结果到JSON文件。
