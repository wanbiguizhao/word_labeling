### 1.2 技术选型

| 层级 | 技术 | 版本 | 说明 |
|------|------|------|------|
| 前端框架 | Vue | 3.5.x | 渐进式 JavaScript 框架 |
| UI组件库 | Ant Design Vue | 4.2.x | 企业级 UI 组件库 |
| 路由 | Vue Router | 4.6.x | Vue 官方路由管理器 |
| HTTP客户端 | Axios | 1.15.x | 基于 Promise 的 HTTP 客户端 |
| 构建工具 | Vite | 6.3.x | 下一代前端构建工具 |
| 后端框架 | FastAPI | 0.x | 高性能 Python Web 框架 |
| 数据验证 | Pydantic | 2.x | 数据模型验证 |
| 数据存储 | JSON 文件 | - | 文件存储标注数据 |

### 1.3 核心架构决策

| 决策 | 方案 | 理由 |
|------|------|------|
| 数据存储 | JSON 文件 | 数据量适中，无需数据库，便于部署和维护 |
| 项目管理 | 虚拟工程项目 | 共享数据池 + 项目视图，避免数据冗余 |
| 标注追踪 | 全局标注注册表 | 跨项目追踪标注状态，避免重复标注 |
| line_id 列表 | 独立文件引用 | 避免 project.json 膨胀，便于维护 |
| 分页策略 | 后端分页 + 缓存 | 减轻前端内存压力，5分钟缓存提升性能 |
| 图片服务 | API 代理 | 统一处理图片路径映射和权限控制 |
| 切割线渲染 | Canvas 组件 | 提供高性能的图形绘制和交互能力 |

##### GET /api/projects

##### POST /api/projects

**功能：** 创建项目

**请求体：**

```python
class CreateProjectRequest(BaseModel):
    project_name: str
    strategy: str = "random"  # pdf/random/al
    pdf_ids: Optional[List[str]] = None
    count: int = 100
    description: str = ""
```

**处理流程：**

1. 校验请求参数（PDF策略需指定pdf_ids）
2. 调用 SelectorService 选择 line_id
3. 创建项目目录和配置文件
4. 生成 line_id_list.json
5. 重新加载项目列表
6. 切换为当前项目

##### DELETE /api/projects/{project_id}

**功能：** 删除项目

**处理流程：**

1. 删除项目目录及所有内容
2. 重新加载项目列表

#### 3.3.2 选择器接口

##### GET /api/selectors/strategies

**功能：** 获取选择策略列表

**返回：** 三种策略（pdf/random/al）及其描述

##### POST /api/selectors/preview

**功能：** 预览选择结果

**请求体：**

```python
class SelectorPreviewRequest(BaseModel):
    strategy: str = "random"
    pdf_ids: Optional[List[str]] = None
    count: int = 20
```

**处理流程：**

1. 获取所有 line_id
2. 排除已标注和暂不标注的数据
3. 按策略选择
4. 返回选择统计和示例

#### 3.3.3 标注图片接口

##### POST /api/images

**功能：** 获取标注图片列表

**请求体：**

```python
class ImageListRequest(BaseModel):
    page: int = 1
    page_size: int = 20
    is_annotated: Optional[bool] = None
    project_id: Optional[str] = None
```

**处理流程：**

1. 获取项目配置
2. 从缓存或文件系统加载图片列表
3. 利用 line_id_set 过滤属于当前项目的数据
4. 根据 is_annotated 过滤
5. 分页返回

**缓存机制：** 使用 `_image_cache` 字典缓存，5分钟有效期

##### GET /api/images/{line_id}/detail

**功能：** 获取标注详情

**处理流程：**

1. 校验 line_id 是否属于当前项目
2. 加载 rule_jsons 原始规则切割数据
3. 加载 lineage.json 后处理合并数据（load_lineage_data）
4. 从 lineage.json 提取该行的合并后字符数据（get_chars_from_lineage）
5. 若 lineage.json 有数据，规则切割线使用合并后数据；否则回退到原始数据
6. 加载 model_jsons / fusion_jsons / annotations 数据
7. 转换为切割线格式（chars_to_lines）
8. 从全局注册表获取标注状态
9. 返回详情数据

##### POST /api/images/{line_id}/annotate

**功能：** 保存标注

**处理流程：**

1. 将切割线转换为字符列表
2. 写入项目 annotations 目录
3. 更新全局标注注册表（mark_annotated）

#### 3.3.4 标注统计接口

##### GET /api/annotation/stats

**功能：** 获取项目标注统计

**处理流程：**

1. 加载项目图片列表
2. 遍历统计已标注、暂不标注、未标注数量
3. 返回统计结果

##### GET /api/annotation/registry-stats

**功能：** 获取全局标注注册表统计

### 3.4 工具函数设计

#### chars_to_lines(chars, image_width)

**功能：** 将字符数据转换为切割线数据

- `col_start` 位置 → 红色线（字符起始）
- `col_end` 位置 → 绿色线（字符结束）
- 按 pos 排序，去重（同一位置只保留一条线）

#### lines_to_chars(lines)

**功能：** 将切割线数据转换为字符数据

- 排序后两两配对，构成字符的 col_start 和 col_end

#### load_lineage_data(project)

**功能：** 加载全局后处理合并数据

- 路径查找：`project_root.parent.parent / lineage.json`（即 datahome/lineage.json）
- 兜底路径：`project_root.parent / lineage.json`
- 返回 lineage.json 的完整数据结构（lines + chars 映射）

#### get_chars_from_lineage(lineage_data, line_id)

**功能：** 从 lineage.json 提取指定行的合并后字符列表

- 从 `lines[line_id].chars` 获取 char_id 列表
- 从 `chars[char_id]` 获取每个字符的 col_start / col_end
- 支持 line_id 格式转换（`line_page_` ↔ `line_page_pdf_`）：当 line_id 不存在时，尝试添加/移除 `pdf_` 前缀后再次查找
- 返回字符信息列表

#### _load_image_cache(project)

**功能：** 加载项目图片列表缓存

- 5分钟缓存有效期
- 利用 line_id_set 过滤属于当前项目的数据

## 七、关键设计决策

| 决策 | 方案 | 理由 |
|------|------|------|
| 数据存储 | JSON 文件 | 数据量适中，无需数据库，便于部署和维护 |
| 项目管理 | 虚拟工程项目 | 共享数据池 + 项目视图，避免数据冗余 |
| 标注追踪 | 全局标注注册表 | 跨项目追踪标注状态，避免重复标注 |
| 规则切割预览数据 | lineage.json 后处理合并数据 | 直接使用已有后处理结果，避免在前端/后端重复执行合并逻辑 |
| line_id 列表 | 独立文件引用 | 避免 project.json 膨胀，便于维护 |
| 分页策略 | 后端分页 + 缓存 | 减轻前端内存压力，5分钟缓存提升性能 |
| 图片服务 | API 代理 | 统一处理图片路径映射和权限控制 |
| 切割线渲染 | Canvas 组件 | 提供高性能的图形绘制和交互能力 |
| 标注页面布局 | 五区域上下结构 | 原始图 + 三方案预览 + 可编辑区，支持对比与快速复制 |
