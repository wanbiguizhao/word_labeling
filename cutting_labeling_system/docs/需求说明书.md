## 一、项目概述

### 1.1 项目背景

本系统是一个**汉字切割标注系统**，用于对已切割的汉字行图片进行切割线校验和修正。系统采用**虚拟工程项目**架构，支持基于选择器（PDF文件、随机、主动学习）动态创建标注项目，实现共享数据池与项目专属标注结果的分离管理。

### 1.2 系统目标

- 提供**虚拟项目**管理能力，一个项目可涉及多个PDF文件
- 支持三种**选择器策略**（PDF/随机/主动学习）筛选待标注数据
- 通过**全局标注注册表**追踪已标注数据，避免重复标注
- 提供四级切割线对比（规则/模型/融合/标注）和在线编辑能力
- 支持标注状态管理（已标注/暂不标注/未标注）

### 1.3 核心概念

#### 1.3.1 共享数据池

所有切割数据（rule_jsons、model_jsons、fusion_jsons、lines）全局唯一存储，供所有项目共享引用，避免数据冗余。

#### 1.3.2 虚拟工程项目

虚拟项目是标注任务的逻辑容器，通过 `line_id_list` 定义项目包含的行数据集合。一个项目可以涉及多个PDF文件的处理结果，项目本身只存储配置文件、line_id 列表和专属标注结果。

#### 1.3.3 全局标注注册表

跨项目追踪所有 line_id 的标注状态，确保选择器在创建新项目时自动排除已标注数据。

## 三、数据需求

### 3.1 数据目录结构

```
datahome/
├── rule_jsons/                    # 共享规则切割结果（全局唯一，原始数据）
├── lines/                         # 共享行图片目录（全局唯一）
├── lineage.json                   # 全局后处理合并数据（规则切割后处理结果）
├── annotation_registry.json       # 全局标注注册表（跨项目追踪）
└── project/                       # 虚拟项目目录
    ├── gwyb1954/                  # 项目ID
    │   ├── project.json           # 项目配置文件
    │   ├── line_id_list.json      # 项目包含的line_id集合
    │   ├── model_jsons/           # 项目专属模型切割结果（模型训练后生成）
    │   ├── fusion_jsons/          # 项目专属融合切割结果（模型训练后生成）
    │   └── annotations/           # 项目专属标注结果
    └── proj_20260705_xxx/
        ├── project.json
        ├── line_id_list.json
        ├── model_jsons/
        ├── fusion_jsons/
        └── annotations/
```

**目录说明：**

| 目录 | 位置 | 说明 |
|------|------|------|
| rule_jsons | datahome/ | 规则切割原始结果，全局共享，离线流水线生成 |
| lines | datahome/ | 行图片，全局共享，离线流水线生成 |
| lineage.json | datahome/ | 后处理合并数据，全局共享，含粘连字符合并结果，区域二数据源（优先） |
| annotation_registry.json | datahome/ | 全局标注注册表，跨项目追踪标注状态 |
| model_jsons | project/{id}/ | 模型切割结果，项目专属，模型训练后生成 |
| fusion_jsons | project/{id}/ | 融合切割结果，项目专属，模型训练后生成 |
| annotations | project/{id}/ | 人工标注结果，项目专属，标注员在线保存 |

#### 3.2.4 全局后处理合并数据 (lineage.json)

```json
{
  "metadata": { "version": "1.0", "created_at": "..." },
  "pdfs": {
    "pdf_gwyb195401": { "pdf_id": "...", "page_count": 30, "total_lines": 37626 }
  },
  "pages": {
    "page_pdf_gwyb195401_42": { "page_id": "...", "lines": ["line_page_pdf_gwyb195401_42_7"] }
  },
  "lines": {
    "line_page_pdf_gwyb195401_42_7": {
      "line_id": "line_page_pdf_gwyb195401_42_7",
      "page_id": "page_pdf_gwyb195401_42",
      "image_path": "lines/line_page_pdf_gwyb195401_42_7.png",
      "width": 2015, "height": 46,
      "chars": ["line_page_pdf_gwyb195401_42_7_char_0", "..."]
    }
  },
  "chars": {
    "line_page_pdf_gwyb195401_42_7_char_26": {
      "char_id": "line_page_pdf_gwyb195401_42_7_char_26",
      "line_id": "line_page_pdf_gwyb195401_42_7",
      "col_start": 1258, "col_end": 1296,
      "width": 38, "height": 46,
      "merged_from": ["line_page_pdf_gwyb195401_42_7_char_26", "line_page_pdf_gwyb195401_42_7_char_27"]
    }
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| metadata | object | 元数据（版本、创建时间） |
| pdfs | object | PDF 信息映射，key 为 pdf_id |
| pages | object | 页面信息映射，key 为 page_id |
| lines | object | 行信息映射，key 为 line_id，包含 chars（char_id 列表） |
| chars | object | 字符信息映射，key 为 char_id，包含 col_start/col_end/width/height |
| chars.merged_from | array | 合并来源（若该字符由多个原始字符合并而来） |

> **说明**：lineage.json 存储规则切割后处理合并结果。区域二规则切割预览优先从该文件读取合并后的字符数据，而非 rule_jsons 中的原始切割数据。
